THE FIVE FACTS THAT DECIDE EVERYTHING
-------------------------------------
A. 334 of 538 neoforge files import only net.minecraft.*, and ~3,500 import lines are vanilla.
   Only 204 files (38%) touch net.neoforged.* (273 @SubscribeEvent handlers over ~45 event
   types; 37 DeferredRegister files; 6 data attachments; 4 ModConfigSpec files; 45 payload
   files; 4 global loot modifiers; 2 biome modifiers; 13 access-transformer lines). So ports
   1-3 are a loader layer on top of mostly shared vanilla-named code. Port 1 is also a
   Minecraft-version change, which hits that vanilla code instead.
B. RENDERING IS THE FRAGILE PART ACROSS MINECRAFT VERSIONS. 26.1->26.2 replaced vertex
   formats (GpuFormat, dynamic VertexFormat builder) and split Gui into Hud. This mod has 62
   files on ModelPart / LayerDefinition / RenderState / EntityRenderer and a DynamicTexture
   path (client/GeneticCoatTextureFactory). 19 mixins, 6 client side, several into render
   classes (EquipmentLayerRenderer, ModelManager, ModelPart, JumpableVehicleBarRenderer).
C. BEDROCK HAS NO RUNTIME TEXTURE API. A pack ships texture files and picks among them with
   Molang (render-controller arrays, entity_multitexture layers, overlay_color tint, at most
   32 entity properties, enums of at most 16 values). The coat can be a bounded layered
   approximation, never the per-pixel gene pipeline. This bends CLAUDE.md hard rule 4's
   premise (a "functionally infinite space"). Owner's call, see treatment 4.
D. 1.12.2 IS JAVA 8 AND SRG NAMES. common/ is Java 17 with ~100-125 record files, ~180
   files using List.of/Map.of/Set.of, ~90 switch statements (arrow forms in ~70-100), ~20
   pattern instanceofs, a handful of sealed/var/text-block uses (counts differ by regex; see
   treatment 5). All ~111k lines of platform code are a rewrite, as are data-driven formats
   (item definitions, trade sets, dimension JSON, jigsaw pools) that 1.12.2 does not have.
E. THE 1.12.2 MARKET HAS REALISTIC HORSE GENETICS (sekelsta; 2.4M CurseForge downloads),
   BUT THE TARGET PACK DOES NOT SHIP IT. The owner pasted The 1.12.2 Pack's full dependency
   list on 2026-10-03: no horse mod of any kind, so no overlap. The pack is on plain Forge
   with MixinBooter (Java 8 likely), 274 dependencies, ~5 GB RAM, pack licence All Rights
   Reserved (the pack author must choose to add us). See treatment 5, piece 1.

RECOMMENDED ORDER (the owner has said all ports ship only after 1.0.0; see RELEASE)
-----------------------------------------------------------------------------------
 1. Fabric 26.1.2 first. It is independent of Minecraft's version, and doing it forces the
    loader seam (events, registries, attachments, networking, config) that makes every later
    Java port cheaper. It also gives Quilt for free (Quilt loads Fabric-API mods).
 2. NeoForge latest AFTER 26.3 leaves beta, and after the Fabric seam exists, so a Minecraft
    bump is done once in shared vanilla code, not twice. Read the 26.2 and 26.3 primers first.
 3. Forge 26.1.2 / any other loader only if a real audience asks. No loader besides Fabric
    and NeoForge is worth it today (Forge's share sits on legacy versions; Quilt's is small).
 4. Forge 1.12.2: only after the go/no-go check passes, and as a reduced-scope mod.
 5. Bedrock last, and only after a one-day spike answers its five open questions and the
    owner decides about the infinite-coat premise.
Do not start port 4 or 5 in the same session as anything else: each is a new product with
its own repo-shaped module.

RULE (owner, 2026-10-03): THE LATEST NEOFORGE BUILD IS THE SOURCE OF TRUTH
--------------------------------------------------------------------------
common/ stays Java 17 and is never lowered. Every other port (Fabric, older or newer
Minecraft, Forge 1.12.2) is derived from the current NeoForge sources by build tooling, not
by maintaining a hand-written second copy. Existing tools surveyed 2026-10-03 (search
snippets; UNVERIFIED until a spike runs each):
- Stonecutter (dev.kikugie.stonecutter): a Gradle plugin that keeps ONE source tree and a
  controller project with one subproject per Minecraft version. A comment preprocessor
  turns code segments on or off, or swaps snippets, per version (// ?if ... style
  directives), over Java, Kotlin and resource files. It targets "compatible release
  versions" (1.21.x to 26.x), not 1.12.2: 1.12.2's API is too different for a comment
  switch. Best fit: Fabric + NeoForge, and neighbouring Minecraft versions.
- Cleanroom is NOT an alternative to Stonecutter. It is a 1.12.2 runtime/loader (Forge
  continuation on modern Java), the thing a 1.12.2 mod runs ON. Stonecutter is a build tool
  for source across versions. Different layer.
- JvmDowngrader: bytecode to Java 8 plus API stubs; the way to ship common/ to 1.12.2
  without changing source.
- MultiLoader-Template (jaredlll08; a 26.1.2 branch): a plain common + one module per loader
  layout; this repo already has the shape. Architectury: not needed.
- Fabric Loom (net.fabricmc.fabric-loom, no remap on 26.x); Mixin and MixinExtras shared across
  loaders; RetroFuturaGradle or Cleanroom's template for the 1.12.2 build.
Open (owner): adopt Stonecutter for the Fabric and later-version ports? Recommended: try
it on the Fabric port first (port 2 piece 1), because that port needs the same source built
for two loaders.
