ELEMENT   The linear gradients inside each traced shape — every one of these files carries `<linearGradient>` blocks with `x1,y1 → x2,y2` running at an arbitrary angle across the drawing.

SHIPPED   Tidewave uses one `RAMP` with `axis: "X"`, `space: "body"`, `from` 0.20 `to` 0.70 — a single horizontal sweep across the whole viewport, shared by all three swells. Elsewhere the gradients collapse to one flat `TOWARD` per tonal band. A viewer sees the colour change along the horse's length instead of along each band's own run, so a swell that rises through the sweep takes the same hue at its crest as the flat band beside it, and the reference's sense of each band being separately lit is gone.

WHY NOT   `RAMP`'s three positional axes are the body basis vectors, and the projection is onto one of X, Y or Z — there is no way to ask for the projection onto an oblique direction. The three non-axes do not reach it either: `noise` wanders and is not monotonic, `cell` is radial per lattice cell, `cellId` is constant per cell with a wall between neighbours. Compositing two ramps does not help, because a layer gets the accumulator as it was before the gene started (rule 8), so a second ramp cannot read the first. This is a different measurement, not different tuning: every existing option measures distance along a fixed basis vector, and an SVG drawing's own gradients are specified by an arbitrary vector in the drawing's plane.

PROPOSAL   A new parameter on `RAMP`, not a new mask.

  `angle` — number, degrees, default `0`. Read only when `axis` is `X`, `Y` or `Z`. Rotates the sweep direction by `angle` within the plane spanned by the named axis and the next axis in `X → Y → Z → X` order, so `axis: "X", angle: 0` is exactly today's behaviour and `angle: 90` is `axis: "Y"`. At a texel it measures the dot product of the body-space position with the rotated unit vector, then normalises that through `from` and `to` as now. Coverage 0 is the `from` end of the rotated span and takes the first colour stop; coverage 1 is the `to` end and takes the last.

  Closest existing thing: `RAMP axis: "X"` itself. The one thing it does that that cannot is aim the sweep at an angle rather than along a basis vector — which is what makes a pasted `<linearGradient>`'s `x1,y1 → x2,y2` expressible, since an exported gradient is almost never axis-aligned.
