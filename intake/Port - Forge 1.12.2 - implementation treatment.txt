Port - Forge 1.12.2 (for The 1.12.2 Pack) - implementation treatment

Scoped with the owner. Every "Decided" line below is her call; "Recommended" lines are the
scoping session's, not asked; "Open" lines are still to be settled, by whom is said on the
line; "UNVERIFIED" lines are facts this file has not proved and the building session must
check first. Source of truth for what exists is wiki/architecture.html (the backport
rationale), wiki/texture-resolution.html (#backport) and wiki/api-notes.html; the shared
evidence is intake/Port feasibility survey.txt. This file is retired (deleted, per

Release: held until 1.0.0, then released (Decided, owner, 2026-10-03).

1. THE REQUEST, AS GIVEN
------------------------
"1.12.2 on forge (to integrate with the highly-used 1.12.2 technic pack)" (owner,
2026-10-03). She named the pack by link when asked:
https://www.curseforge.com/minecraft/modpacks/the-1122-pack/files/all  - "The 1.12.2 Pack"
(CurseForge; a Technic version exists; 200+ mods including IC2, BuildCraft, Thaumcraft,
Twilight Forest, Thermal Expansion, AE2, Galacticraft; recommended 5 GB RAM: search snippets,
UNVERIFIED). Decided (owner): that pack is the integration target. Read as: a Forge 1.12.2
mod, Java 8, MCP/SRG names, that adds procedural horses to that pack.
Note: Tekkit Legends is 1.7.10 and is NOT the target; the tool results behind this are
UNVERIFIED beyond a search snippet.

2. IN SCOPE, AND WHAT IS NOT
----------------------------
In: the go/no-go check; common/ compiled for Java 8; a forge-1.12.2/ module with genetics,
coats, breeding, a few items; the refmap and Mixin via MixinBooter (or no mixins).
Not in (re-askable): the hay-bale portal, dimension and stables; the cowboy and horseman
villagers and the barn; carts; stasis chambers; the H menu; tack and gear slots; the web
tools (unchanged); every compat hook.

3. WHAT ALREADY EXISTS
----------------------
- common/ is built with Java 17 (common/build.gradle.kts, a 17 toolchain, with a comment that
  a 1.12.2 backport "pays a source downgrade, mostly the records"). Hard rule 2 says so. The
  guard test is CommonPortabilityTest (TeaVM's JDK subset, NOT Java 8).
- Java-language use in common/, measured 2026-10-03 (counts of files; two greps gave 104 and
  124 for records, so treat it as 100-125; re-measure with rg per construct):
  records ~104-124 (the main cost); List/Map/Set.of / copyOf ~180; switch statements ~90 (arrow
  forms ~70-106); pattern instanceof ~20-30; sealed/permits 4; var 4; text blocks 2;
  String.repeat/strip/isBlank/lines ~14; Files.readString/writeString 11-12; java.awt /
  javax.imageio 7 files (coat/pattern 3, coat/skin 1, genetics/genes 1, genetics/spec 2) - to
  be checked as tool-only; Stream .toList 2. About 300 of 389 files are likely touched.
- Prior art in the wiki (wiki/texture-resolution.html #backport): a 26.1.2-vs-1.12.2 table;
  the 1.12.2 audience may have 2048/4096 GL_MAX_TEXTURE_SIZE and 32-bit JVMs, so 8x is the
  ceiling with a runtime cap; OptiFine .jem custom models would replace the horse mesh.
  api-notes.html: a 1.12.2 backport needs the mixin refmap back.
- The coat pipeline returns int[] (common/coat/pattern/CoatTextureComposer); 1.12.2 has
  DynamicTexture, so the texture glue is a small translation, but the model/layer glue is
  not (below).
- NOT portable, rewrite in Java in 1.12.2 (no data-driven equivalent, UNVERIFIED but
  believed): item definitions (142), trade sets/villager_trade (91), dimension_type/dimension,
  jigsaw pools, structures, loot modifiers, biome modifiers, data components, attachments,
  ValueInput/Output. 1.12.2 uses NBT, capabilities, SimpleNetworkWrapper, VillagerRegistry
  careers with ITradeList, DimensionType + WorldProvider, ModelBase/ModelRenderer,
  LayerRenderer, GuiScreen with no widgets, no gametest framework.
- A big existing neighbour: "Realistic Horse Genetics" by sekelsta (Horse Colors): 2.4M
  CurseForge downloads, CC-BY 4.0+ assets, LGPL 3+ code, 1.12.2 and 1.14.4-1.20.1 builds,
  genes: extension, agouti, dun, cream/pearl, gray, silver, tobiano, roan, frame, splash,
  sabino, dominant white, leopard, mushroom, champagne; it also touches size, speed, health,
  jump. Whether The 1.12.2 Pack ships it (or Animania, Mo' Creatures, Gender Mod) is
  UNVERIFIED.
- LOOKS built but is not: there is no forge-1.12.2/ module and no Java 8 build of common/.

4. THE PIECES
-------------
Piece 1 - Go / no-go: what horse mods does the pack ship, and may we join it?
  Player sees: nothing. Output: a note on architecture.html's Verification tab.
  Decided (owner): flag the Realistic Horse Genetics overlap as a go/no-go check, not an
    assumption either way. Decided (owner, 2026-10-03, later): The 1.12.2 Pack has NO horse
    mods. So the overlap check is satisfied for the pack as shipped; Open 1 shrinks to "a
    player who adds Realistic Horse Genetics beside us" (a clash to test, not a blocker), and
    the remaining piece-1 work is licence and the pack author's willingness only.
  Steps: read the pack's mod list (CurseForge and Technic /mods pages: the surveying session
    could not); check for Realistic Horse Genetics, Animania, Mo' Creatures, Horse Stats;
    read each licence; ask the pack author whether they would add a mod (Technic is
    Solder-based; there is no central submission, UNVERIFIED).
  Open 1 (owner): if the pack ships Realistic Horse Genetics: build a complement (breeds,
    items, care, portal, no coat genes), a replacement, or stop? CC BY-NC 4.0 permits free
    redistribution with credit; a paid server host may count as commercial (a legal
    question: the owner).
  Tests: none. Play checks: none. This piece is research and is S.
Piece 2 - common/ builds on Java 8
  Player sees: nothing.
  Recommended: add a second compile of common/ at --release 8 as a build variant (the Java 17
    source stays the truth for NeoForge and web/), and downgrade the 100-125 records and
    the ~180 collection factories in a mechanical way. Jabel covers switch expressions and
    var but (UNVERIFIED) not records; records would be hand-expanded or generated.
    Open 2 (owner): rewrite common/ in place to Java 8 (one codebase, loses records for
    everyone), or keep Java 17 as the source and GENERATE a Java 8 copy (a tool, delombok-style,
    tested by running common's tests on it). Recommended: a generator, because it leaves the
    shipped NeoForge build untouched.
  Code: build tooling in common/; any hand fix goes in common/ (rule 1).
  Data and saves: unchanged; genotype codes are version-neutral strings.
  Tests: :common:test on the Java 8 copy (167 test files; JUnit 5 supports Java 8), plus a
    guard like CommonPortabilityTest for Java-9+ APIs under --release 8. A full :common:test
    run is a release-weight job: hard rule says never run it unless asked (Open 3, owner).
  Docs: architecture.html (fix the stale "no Java 9+" line), decisions.html (Java level).
Piece 3 - forge-1.12.2/ skeleton and the horse
  Player sees: a modded horse that spawns with a generated coat, in The 1.12.2 Pack.
  Code: a module (RetroFuturaGradle or Cleanroom's template; Open 4, building session) with
    an EntityHorse renderer layer that swaps the texture from the genotype, per-entity data
    in NBT or a capability, MixinBooter mixins only where Forge events cannot do it (the
    refmap comes back: api-notes.html). Textures: DynamicTexture with a runtime cap (the
    texture-resolution page).
  Data and saves: NBT; the genotype code string plus epigenome code, the same as the Java
    record. A 1.12.2 world is separate from a 26.1.2 one; nothing migrates.
  Config: Forge Configuration. Sync: SimpleNetworkWrapper for what the client needs to draw.
  Tests: unit tests in common/ cover genetics; the rest by yard play.
  Play checks: a spawned horse renders; breeding passes genes; the world reloads with the same
    coat; a second horse mod in the same pack does not crash it.
Piece 4 - Breeding, names, stats, a few items (reduced scope)
  Player sees: names, pedigree, breeding that inherits, a few items (gene carrots, a
    research book).
  Open 5 (owner): which items. Recommended: the genetics carrots and the research paper only.
  Code: common/ already holds the logic; the module translates it.
Piece 5 - Everything else (re-askable)
  The realm/portal, villagers, carts, stasis and the H menu: each is a rewrite in a different
  API and is out of scope until the owner asks, one by one.

5. DECISIONS
------------
A Ask: the owner wants the mod in that pack. The smallest version worth having is
  pieces 1-4 without piece 5.
B Fit: no philosophy change. D, E: genetics and breeds live in common/ and port with it;
  breed JSON loads the same. F Items: 1.12.2 item model JSON is the older format; a few
  items only. G Config: Forge annotations. H Saves: own world; a 1.12.2 save does not carry
  to Java 26.1.2. I Multiplayer: 1.12.2 networking is hand-built.
J Compatibility: Realistic Horse Genetics (Piece 1), plus whichever horse mod the pack ships.
K Performance: 32-bit JVMs and 4-5 GB packs; cap texel budget (TexelBudgetCache exists).
L Testing: no gametest framework on 1.12.2; yard play checks.
Open 6 (owner): the version line: a separate 0.x for the 1.12.2 jar? Recommended: yes.
M Release: Decided, held to 1.0.0.

6. UNVERIFIED (riskiest first)
------------------------------
1. Which mods the pack ships, and its Forge build. Check: CurseForge / Technic /mods.
2. Whether Jabel supports records (believed no). Check: Jabel's README and a test compile.
3. Whether the audience's Java is 8 or 21 (Cleanroom): the target pack's launcher decides.
4. Whether DynamicTexture on 1.12.2 is cheap enough at the coat resolution used today.
5. Forge 14.23.5.2860 is the last build. 6. MCP names (stable_39) vs Mojang names.
7. A published example of a successful modern-to-1.12.2 backport: none found.
