What already exists, so the building session does not redo it
==============================================================
- wiki/item-whistles.html already has Gameplay, Coding, a Roadmap tab (with its
  note.roadmap-summary box) and a Verification tab. Extend it. Do not add a page.
  If the Roadmap summary sentence changes, re-run bake-roadmap-index.mjs; if the
  Verification tab changes, bake-verification-index.mjs.
- item/WhistleItem.java: one class, radius 16/32/64. use() -> recall(): every
  tamed, owned, unridden horse in the box that is not already within 3 blocks
  gets HorseLeads.untieFor, navigation.stop(), then snapTo(spreadSpot). Always a
  teleport. Cooldown 60 ticks.
- item/EnderWhistleItem.java + server/EnderWhistleCalls.java: BOUND_HORSE
  component, bind on EntityInteract using HorseOwnership.bindRefusal, call()
  (loaded -> deliver; else portal ticket + PENDING wait), dust check once a
  second. deliver() re-checks ownership at call time and teleports.
- server/BondFollowGoal.java already walks a tier 2-3 horse to its owner using
  ReachCheck (a real navigator path, not sight), MAX_FOLLOW 32 blocks. It is the
  template for "walk in", and its canUse() refuses leashed, ridden and no-path
  horses, which is exactly the rule a walked call needs too.
- Bond tiers: HorseCareAttachment.behaviourTier() - 31 / 61 / 81 -> tier 1 / 2 / 3.
  Bond decay floors at 31, so a bound horse can never fall below tier 1.
- client/HorseBrowserKeyBindings.java is the template for a production
  keybind (RegisterKeyMappingsEvent, KeyConflictContext.IN_GAME, KeyMapping.Category.MISC).
  network/TackSlotPayload.java + ModNetworking is the template for a client ->
  server payload that the server treats as a claim, not a fact.
