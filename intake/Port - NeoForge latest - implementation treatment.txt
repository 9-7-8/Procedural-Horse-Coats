1. THE REQUEST, AS GIVEN
------------------------
"neoforge on the absolute latest version of mc" (owner, 2026-10-03). Read as: the same mod,
same NeoForge loader, moved from Minecraft 26.1.2 to the newest Java release. As of
2026-10-03 that is 26.3 (released 2026-09-15) with NeoForge 26.3.0.40-BETA; 26.4 snapshot 1
(2026-09-22) is the next target after it. "Absolute latest" is a moving target: see Open 1.

2. IN SCOPE, AND WHAT IS NOT
----------------------------
In: bump minecraft_version / neo_version in gradle.properties (now 26.1.2 / 26.1.2.100);
module rename or a second module (Open 2); fix every compile break; the 26.2 and 26.3
primers' behaviour changes; re-run every bake and the gametests; migrate saved data only if
a format moved (it should not).
Not in: dropping 26.1.2 (Open 2); any new feature; Fabric (port 2); a Vulkan-specific
renderer (the Vulkan backend is vanilla's job, but the dynamic texture path must survive it).

----------------------

  neo_version=26.1.2.100, mod_version=0.5.040. settings.gradle.kts includes
  :neoforge-26.1.2 (the module's name carries the version).
- The version-fragile surface, measured 2026-10-03 in neoforge-26.1.2/src/main/java/com/
  example/horsegenetics/neoforge/:
  * Rendering: client/GeneticCoatTextureFactory (DynamicTexture / NativeImage upload),

    GeneticHorseRenderState, CowboyRenderer, HayPortalRenderer, EmissiveCoatLayer,
    AttachedPartLayer, carts/client/renderer/*. 62 files use ModelPart, LayerDefinition,
    RenderState or EntityRenderer.
  * 19 files in mixin/ (13 common, 6 client in mixins json; refmap removed, issue 16). Only
    FadingGearMixin uses MixinExtras. api-notes.html warns Mixin cannot inject into interface
    private static methods, which 26.1.2 uses a lot.
  * Serialization: 13 files on ValueInput/ValueOutput, 14 on CompoundTag, 125 on Codec, 72 on
    StreamCodec (payloads and attachments); data/ModAttachments registers 6 attachments.
  * Data: 144 recipes, 112 advancements, 71 villager_trade + 20 trade_set, 12 worldgen JSON,
    4 structures, 2 dimension_type, 2 dimension, 142 item definitions. 26.3 renamed
    worldgen/configured_feature to worldgen/feature (config inlined) and added a

- The portable guard rails: common/ is untouched by a Minecraft bump (hard rule 1), so
  :common:test is not expected to change. Gametests: gametest/ModGameTests.java (2.5k lines).
- Prior art: the 1.21.x -> 26.1 move already happened; wiki/api-notes.html is the record of
  its quirks. Read it before touching an unfamiliar system.
- LOOKS built but is not: nothing exists for 26.2/26.3. neo_version and the module name are
  hard-wired to 26.1.2 in several places (grep "26.1.2" across build files, run configs,
  wiki/architecture.html, the release procedure).

4. THE PIECES
-------------
Piece 1 - The mod builds and boots on the latest NeoForge (a platform bump)
  Player sees: the same mod, loading on the newest Minecraft.
  Decided: none beyond the Release line.
  Recommended: bump one version at a time (26.2, then 26.3), reading each primer and
    committing after each, rather than jumping straight to 26.3. It localises breaks and the
    26.2 stable NeoForge exists to bump onto.
  Recommended: do not start until NeoForge 26.3 leaves beta (see Open 1).
  Code: neoforge module only; common/ must not change.
  Data and saves: none expected. A world saved on 26.1.2 loads in the later version through
    vanilla's data fixers. Registry ids and attachment ids stay. If a codec changed,
    migrate it (hard rule 10); the worldgen JSON rename is a datapack change, not a save
    change, but the mod's own structures and dimension must still load an old world: test
    it with a 26.1.2 save that has a hay portal and a stable.
  Sync: payloads rebuilt on the same StreamCodecs; check the registrar API.
  Config: none.
  Tests: the whole existing suite is the proof. :neoforge-26.1.2:build, the gametests, and
    one boot with generated files deleted (add-a-config-option's boot check).
  Play checks: a horse's coat renders (not white or purple-black) on the Vulkan and OpenGL
    backends; tack renders on a ridden horse; portal, dimension, a stable, a villager trade
    and the H menu open. These become the Verification tab on architecture.html.
  Docs: architecture.html (versions, module name, running the game), api-notes.html (new
    quirks), releases.html (the supported-versions line).
Piece 2 - Rendering and mixin repairs
  Player sees: nothing different; the mod still looks and rides right.
  Recommended: do this as the main body of piece 1 in practice; it is separate here only so
    it can be sized. Expect the dynamic texture path, GeneticHorseRenderState extraction,
    HdHorseModel's 2x cube trick, the render-class mixins and the jump-bar mixin to break.
  Code: neoforge module; a pure sampling change belongs in common/ (rule 1) only if the
    coat int[] contract itself must change (it should not).
  Tests: GeneticCoatTextureFactory behaviour is covered by yard play checks, not unit
    tests (UNVERIFIED that any covers it); add a render smoke gametest if one is cheap.
  Play checks: the photograph-horses procedure on a fixed genotype list; compare with a
    26.1.2 shot set taken first (take them BEFORE the bump: Open 3).

5. DECISIONS
------------
A. Ask: Open 1 - which version is "latest" when it is built? Settled by the owner at build
   time. Recommended: the newest NeoForge that is not -beta.
B. Fit with the mod (philosophy, decisions): untouched; no feature changes. Does not apply:
   items, genetics, breeds, config, gene-making.
C-L: does not apply, because this changes no gameplay. Exceptions: H saves (above),
   J compatibility (the bundled compat hooks Jade, Waystones, FTB Teams, HorsePowered in
   neoforge/compat/ each need a release for the new version; if one lags, gate it behind its
   mod being loaded, which is already how it is written - UNVERIFIED, read compat/), and
   K performance (Vulkan changes texture upload cost; re-run /stress-test once).
Open 2 (owner): keep 26.1.2 alive beside it? The cheapest is the new version only. Keeping
   both means a second module (neoforge-26.3 sharing sources through a Gradle source set,
   or Stonecutter, which has experimental 26.1.2 nodes). Recommended: new version only and
   keep the tag for the last 26.1.2 release.
Open 3 (building session): take baseline photographs on 26.1.2 first.

5. Whether Jade, Waystones, FTB Teams, HorsePowered exist for the target version.
