Port - any other modloader on 26.1.2 - implementation treatment

Scoped with the owner. Every "Decided" line below is her call; "Recommended" lines are the
scoping session's, not asked; "Open" lines are still to be settled, by whom is said on the
line; "UNVERIFIED" lines are facts this file has not proved and the building session must
check first. Source of truth for what exists is wiki/architecture.html; the shared evidence
is intake/Port feasibility survey.txt. This file is retired (deleted, per /process-intake
step 8) as each piece ships or is dropped.
Release: held until 1.0.0, then released (Decided, owner, 2026-10-03).

1. THE REQUEST, AS GIVEN
------------------------
"any other modloader on 26.1.2 on java" (owner, 2026-10-03). Read as: besides NeoForge and
Fabric, which Java-edition loaders could run this mod on 26.1.2, and what each costs.
This treatment surveys them and scopes only the ones worth building.

2. IN SCOPE, AND WHAT IS NOT
----------------------------
In: Quilt (compatibility check of the Fabric jar); MinecraftForge 26.1.2 (a platform
module); a written verdict for the rest.
Not in: Sponge (a server-plugin platform, not a mod loader: it cannot add items, entities or
client rendering); Legacy-era loaders (LiteLoader and similar, dead); Ornithe and other
version-bridging forks (they target old versions, UNVERIFIED for 26.1.2); Sinytra Connector
and similar bridges (they let players run Fabric mods on NeoForge; they are not a build target).

3. WHAT ALREADY EXISTS
----------------------
- Only NeoForge. No other loader's code, build or doc exists (grep Quilt|Forge across
  common/, neoforge-26.1.2/, wiki/text/: the only hits are the 1.12.2 backport notes and
  Forge-era NeoForge history).
- The survey's loader table (UNVERIFIED, search snippets only):
    MinecraftForge: a 26.1.2 build exists (64.1.3 latest, 64.1.0 recommended); its share is
      on legacy versions; a near-sibling of NeoForge with different event and registry
      details.
    Quilt: loader last updated 2026-09-05; Quilted Fabric API is archived as of 26.1; Quilt
      usually loads Fabric mods that need only Fabric API; small share.
    Architectury API 20.1 supports 26.1.2 but is not actively maintained on 26.1.x. The
      project already has a common/ + platform layout, so it is not needed.
    MultiLoader-Template has a 26.1.2 branch; Stonecutter has experimental 26.1.2 nodes.
- Prior art: the port-2 treatment's seam (shared module + one platform module per loader).

4. THE PIECES
-------------
Piece 1 - Quilt works with the Fabric jar (a test, not a build)
  Player sees: the Fabric jar listed as Quilt-compatible.
  Recommended: do not build a Quilt module; boot the Fabric jar on Quilt and write down the
    result. Cost: a server boot and a client boot.
  Code: none. Config/Sync: none. Data and saves: none.
  Tests: a Quilt boot with Fabric API; play checks: the yard run.
  Docs: compatibility.html. Waits on: port 2 piece 2.
Piece 2 - MinecraftForge 26.1.2 (optional; build only if someone asks)
  Player sees: a Forge jar.
  Recommended: skip until an audience asks. NeoForge forked from Forge and a lot of the
    facility names are the same, but the event bus, registries, networking and config
    details differ (UNVERIFIED how far on 26.1.2), and Forge on 26.2+ has thin stable
    mod coverage.
  Open 1 (owner): build it at all?
  Code: a third platform module on the port-2 shared seam (port 2 piece 1 must exist first).
  Config/Sync/Saves/Tests: as port 2's; play checks: the yard run.
Piece 3 - A written verdict on the rest
  Player sees: nothing; it answers "why no X". Docs: the compatibility page's "Supporting
    other loaders" paragraph, with the reasons above and the date.
