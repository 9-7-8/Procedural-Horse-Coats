2. RISKS (what could break it, or be broken by it)
- SAVES. The refuse-without-add-on rule can strand a server owner after a jar swap; the override key and the message are the mitigation. The new optional
  Base-sex key is the only new saved field on a record; it must never disagree with a genome.
- THE HORSE RECORD IS EVERYWHERE (79 call sites). Splitting its API is the biggest edit; do it one package at a time.
- ORDER-SENSITIVE STARTUP. Gene order and the class-load registrations decide genotype codes and registry order. Compare dumps.
- MIXINS. Each jar needs its own json; "required: true" with defaultRequire 1 means a mixin that fails to apply crashes at load. Boot every combination.
- CLIENT/SERVER SPLIT. A client-only class in a common mixin list crashes a dedicated server.
- DESIGNER TWIN (rule 5). Moving classes between modules must not desynchronise the browser designer and CustomHorseSpawnScreen.
- PERFORMANCE. One shared slow tick; do not add a pass per jar. Measure with procedures/stress-test.txt if a subscriber list adds cost.
- MODDED CONTENT. Compat classes load only when their owning jar is present; generated armour, carts, gates and jumps read the live registry.
- PLAYER MISTAKES. Installing the all-in-one next to a part, or an add-on without Base: the incompatible/required declarations and the launch message are the
  mitigation (file 06 step 8). Test every wrong combination.
- THE RENAME. This plan assumes it shipped. If its converter slips, this plan waits.
- COMMAND WHISTLE IS NOW FULLY ON MAIN (0.5.042-0.5.043; its treatment is retired). It added C/care/CommandWheel, HorseOrder and HorseOrders and N/server HorseOrdering,
  OrderCombatGoal, OrderFollowGoal, OrderGrazeGoal, OrderStayGoal. It belongs in Base, BUT HorseOrders imports common.genetics.Gene: the "fighter" test (Hunt monsters, Defend
  me, Guard need a horse bred to fight) reads a gene. That is a Base-to-Breeding import. Resolve in piece 1 step 4: add a hook (e.g. OrderEligibility) in Base whose default
  allows only the orders that need no gene, and Breeding supplies the fighter test. OPEN for the owner: without Breeding, are the combat orders hidden (recommended) or
  available to every horse? Re-run the dependency scan against main, not against the survey. Bridle/saddle split,
  horse shoes, troughs and the port treatments edit the same screens and registries: sequence them around, not inside, a piece here.
- THREE LIKELY PLAYER FAILURES: (1) a jar swap strands a world (refusal) - tested both ways; (2) all-in-one plus a part - declared incompatible; (3) one jar's
  screen or task calls a class from a missing jar and crashes - the import-scan test and the combination matrix.
