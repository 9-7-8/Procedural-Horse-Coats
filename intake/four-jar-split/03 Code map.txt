FOUR-JAR SPLIT - 03 CODE MAP

What exists today, the seams that force work, and which jar each class goes to. Sources: a
read-only survey of common/ and neoforge-26.1.2/ by two agents plus a direct read of the files
named (2026-10-03). The class LISTS are from directory listings and are exact; the OWNER of each
class is a proposal that follows the owner's decisions (file 01) and, where she did not decide, a
rule of thumb. The building session confirms every proposal with a dependency scan before moving a
class (see file 04, step 1). Counts are as of that date; re-count before quoting.

  C   = common/src/main/java/com/example/horsegenetics/common/

----------------
- settings.gradle.kts includes :common, :neoforge-26.1.2, :web. One jar: neoforge-26.1.2/build.gradle's
  'jar' task copies :common's compiled classes in (excluding *Tool classes, example-genes), plus
  LICENSES/LICENSE/LICENSE-ART/THIRD_PARTY_NOTICES.md under META-INF.

  breed 23, horse 18, trait 16, parts 15, repro 11, care 9, name 4, herd 4, stable 3, cart 2, log 2,
  realm 2, wild 2, progress 1.

2. THE SEAMS (each is a single hard-coded file today)
-----------------------------------------------------
S1  N/HorseGenetics.java (132 lines): the one constructor. Order matters. Gene and breed specs load
    first (ModGeneSpecs.load, api/GeneRegistration.listen, ModBreedSpecs.load, ModPersonNames.load,
    BreedSpawningConfig.register): gene order lengthens the genotype code. Then DietFoods.verify and
    HorseTackSlot.verify, then DeferredRegisters: ModAttachments, ModDataComponents, ModBlocks,
    ModBlockEntities, ModParticles, ModMenus, ModItems, ModEntities, ModAttributes, ModPoiTypes,
    ModVillagerProfessions, ModRecipes, three loot registers, ModBiomeModifiers, ModStructureTypes,
    ModTriggers, ModGameTests; creative tabs ModCreativeTabs.TABS ("main" and "breeds").
    CLASS-LOAD TRICKS: ModdedMaterials.scan(), ModdedArmour.init(), DoubleGates.init() and Jumps.init()
    must run BEFORE ModBlocks/ModItems attach to the bus: they register into those registers as the
    classes load. HorseCarts.init() registers through RegisterEvent. This is the nastiest seam.
S2  N/network/ModNetworking.java (942 lines): all 44 payloads in one RegisterPayloadHandlersEvent
    method; handlers inside the same file (handleTackSlot near :604, handleOpenHorseGear near :662).
S3  N/data/ModAttachments.java: 17 attachment types (horse_record, horse_care, hunger, horse_social,
    horse_repro, cart_metres, pregnant, jump_screen_known, horse_cooldowns, armed_carrots,
    cowboy_brand, passification, riding_pass, horse_gear, lycan_shift, realm_return, leash_placer).
    horse_record serialises through HorseRecordCodecs.MAP_CODEC.
S4  ModMenus, ModItems (item/ModItems 590 lines), ModBlocks, ModBlockEntities, ModDataComponents,
    ModEntities, ModAttributes, ModLootFunctions, ModLootModifiers, ModCreativeTabs: monolithic registers.
S5  N/ServerConfig.java (one SPEC, about 1394 lines) and N/ClientConfig.java (about 681 lines), written
    to phc/server.toml and phc/client.toml. The carts already keep their own two files
    (carts/CartsConfig; horsegenetics-carts.toml and -carts-client.toml).
S6  N/client/HorseInfoScreen.java (about 2300 lines): a private Tab enum of eight tabs (Overview, Gear,
    Genes, Health, Coat, Other genes, Offspring, Family tree). Gear tab, doll, picker, Dress button and
    drawDraught (uses CartDraft, CartKind, CART_METRES) are embedded in it.
S7  N/client/HorseBrowserScreen.java (about 4500 lines): a private Tab enum of ten tabs (Getting started,
    Recipes, My horses, Horse realm, Query, Breeding preview, Log, Gene database, Alleles, Breeds).
S8  N/client/TutorialPage.java: chapter-to-task mapping, about 69 ProgressTask references, about 8 cart
    pages. C/progress/ProgressTask.java: one enum of 103 constants (grouped Wild 19, Husbandry 29,
    Genetics 18, Farming 11, Magic 10, Basic breeding 8, Projects 5, People 3), completed through
    N/server/HorseProgress.complete from about 44 files. One advancement trigger (ModTriggers.PROGRESS_TASK)
    is data-driven off the enum.
S9  N/server/HorseRecords.java and C/horse/HorseRecord.java. HorseRecord has 15 fields: id, firstName,
    lastName, barnName, geneticCode, epigenomeCode, breed, motherId, fatherId, tamedBy, bredBy,
    generation, parentStats, gelded, ownerId. Sex is not a field: it lives inside geneticCode
    ("horsegenetics.sex", X/Y) and is read through sex(). Speed/health/jump/size are not stored: they
    are computed from genome and breed (Traits). HorseRecords. is used in 79 neoforge files; Genotype in 43.
S10 N/server/HorseCareHandler.java (554 lines): ONE slow tick doing bond, hunger, healing, the herd flag,
    the gelded bond bonus and breed-based progress awards (MEET_DHAMPIR, MEET_MAGICAL_HERD). Hunger drains
    by the vanilla SCALE attribute, not the genome (C/care/Hunger.java); healing is gated by the diet
    locus through HorseDietHandler.canRegenerate.
S11 N/mixin: 20 mixin classes (listed in section 5), one config file.
S12 N/api: only RegisterHorseGenesEvent and GeneRegistration (genes). Javadoc: "Unverified against 26.1.2
    in a running game". Documented on wiki/api-reference.html and wiki/api-notes.html.
S13 N/compat: WaystonesCompat, FtbTeamsCompat, HorsePoweredCompat, JadeHorsePlugin (guarded by
    ModList.isLoaded), plus GeneratedArmour, GeneratedCarts, GeneratedGates, GeneratedJumps, GeneratedPack,
    ModdedArmour, ModdedMaterials, MaterialScan, HayBales.

THINGS THAT LOOK BUILT BUT ARE NOT
- There is no extension API for tabs, rows, tasks, payloads or items.
- Shoes, saddle pads, saddlebags, bridles and halters are slot enums and planned wiki pages only. The 17
  gear item tags under RES/data/horsegenetics/tags/item/gear/ are empty except mane.json and tail.json
  (both hold rescuing_braid). Horse speed does not read shoes.
- common/ is not organised by jar. Hunger, bond, herd, braid and send-home logic sit together in C/care/
  and C/herd/.
- "Wild herds" (HerdManager) is breed-heavy, so it is Breeding despite the name; the plain wild upkeep is
  WildTurnover/WildTopUp.
- There are NO tack items to put in the gear slots yet (the Gear tab works; almost nothing is wearable
  except the vanilla saddle and barding, dyed tack and the braid).
