Equine Research Shelf
(Block / genes)
A bookshelf that files research papers — one of each allele pair — and copies any of them onto blank books for as long as the original stays in it. It is what turns knowing a gene into owning it.

Real slots, one paper per allele pair EquineResearchShelfBlockEntity holds a 54-slot container ( SLOTS , a double chest) saved with ContainerHelper . It was a Set<String> of keys fed through one filing slot and read back through a clickable list; in play that read as a shelf that did nothing, and the owner asked for it to be “just a UI like a chest” (2026-09-10). The one-per-pair rule the set used to make structural is now a slot rule: PaperSlot.mayPlace refuses a paper whose pair another slot already holds, and every slot takes one item. The key is the pair, and that is the whole change Every static on this block entity used to take a gene key and now takes a ResearchTopic.token() — topicOf , topicsIn , holdsElsewhere , stores , displayName , copyTicks , the saved selected string, and ShelfActionPayload . Nothing about the shelf's shape moved; what moved is what counts as “the same paper”, since a paper names a pair now. Two consequences worth knowing. The Copy list is much longer — a locus you have studied contributes several rows, and the flat Gene: pair list sorted by gene name was chosen over grouping rows under a gene heading because it needed no new row-type handling in the screen or the menu sync (owner's call, 2026-09-24). And copyTicks is still the gene's rarity , not the pair's: what is rare is the locus, and a carrier paper is no easier to transcribe than a true-breeding one. A pick saved before the change is a bare gene key, which no longer matches any filed paper, so the shelf simply has nothing selected and the player picks again. A filed paper is migrated properly — see the one piece of back-compat . Breaking it drops the contents from the block entity’s preRemoveSideEffects , where vanilla’s chests do it. The old shelf dropped from the block’s affectNeighborsAfterRemoval , which runs after the block entity is already gone — so as far as the code shows, breaking a filled shelf used to lose the lot. Two tabs, one set of slots each ResearchShelfMenu has the 54 paper slots (Store) and a book slot and a result slot (Copy). Which are live is the tab, through Slot.isActive() rather than moving them: Slot.x and Slot.y are final, and isActive() is what vanilla consults for drawing and hit-testing. The tab is only known on the client, so on the server every slot is live — the client never sends a click on a slot it is not drawing. Because the papers are real slots the ordinary container sync carries them, and the Copy list is read from those slots on both sides ( topicsIn ). The only packet left is ShelfActionPayload ’s pair pick; the old ShelfSyncPayload and the withdraw action are gone. The copy runs on the block, like a furnace The book slot, the result slot, the picked pair and the progress all live on EquineResearchShelfBlockEntity , and its ticker advances them whoever is looking. The menu only wraps them - its slots are the block’s containers and its progress bar reads the block’s ContainerData , the furnace’s dataAccess pattern. The copy used to live on the menu, which only exists while a player has the screen open, so it stopped the moment they clicked off (owner-reported 2026-09-10). A finished copy spends one book; the pick reaches the client as an index into the Copy list ( DATA_SELECTED ), since a ContainerData can only carry ints. Its labels are window-relative. AbstractContainerScreen translates to (leftPos, topPos) before calling extractLabels , and the shelf used to add them again, which threw the title and the inventory label off the window. The last tab is a static on the screen, so it holds for the session. Verified The shelf window fits and files (closed 2026-09-09, on the second attempt). The first fix moved the layout constants onto the menu and was written up as closed without anyone opening the window, which was still rough: “text all over the place and you still can't put items in it” . Four captions were wider than the 176px window and drawn with raw g.text ; they go through drawFitted now. The filing slot had been inactive on the server for the life of the block, because isActive() read a storeTab field only the client sets; slot activity is side-aware now. It stores papers (owner, the third play session of 2026-09-10).
