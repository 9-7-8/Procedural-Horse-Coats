Skittishness
(Magical gene / no coat effect)
What a horse runs from, and when. The mirror of aggression , allele for allele — and being ridden makes no difference to it at all.

Gene key horsegenetics.skittish Alleles the same grid as aggression , plus n Inheritance homozygous recessive, and recessive to the other variants Reaches the game as a temper effect with "mood": "flee" Coat effect none, ever Fleeing was once implemented somewhere else entirely Until 2026-09-17 the temper verb returned early on any mood that was not aggressive , and fleeing was implemented in NightBehaviourHandler against the night verb instead. When this locus moved onto the shared verb the flee path had to move with it, into GeneAbilityHandler.flee . Had it not, this gene would have loaded, registered, baked, appeared in the census and done nothing whatsoever — which is the failure mode this codebase keeps paying for. If you add a mood, follow it all the way into the translator. “Herds” must not include the horse's own band passive excludes every equine in MobGroups . It is the whole of gap 241 below, and the exclusion moved from the night handler's private matcher into the shared group resolver when this locus was built — where every caller gets it rather than one. There is no vanilla avoid-goal to borrow Fleeing is a navigation call rather than a goal: the horse paths to a point FLEE_DISTANCE directly away from the nearest match and drops any target it had. Log whether the path was accepted. From outside, a flee that never fired and a flee that fired into a fence four blocks away look exactly alike, and Navigation.moveTo 's return is the only thing that tells them apart. The candidate predicate is not only MobGroups.matches . Since 2026-09-25 it also asks !Passification.suppresses(horse, c) , so a player who has paid this horse is filtered out before the nearest match is picked and cannot be the thing it runs from. Passification counts its chokepoints, and flee is the fifth — it was missing while that page promised there were four, which is worth knowing before adding a sixth. Dropping the reason is not enough here, because the leg is already issued Every other chokepoint guards a target , which is re-read each tick, so forgetting it is the whole fix. This one issues a moveTo FLEE_DISTANCE blocks away and only re-picks on the temper beat, so a horse calmed mid-flight would run the leg out and turn round at the far end — which looks, from across a paddock, almost exactly like it working. Passification.forget therefore calls GeneAbilityHandler.stopFleeingFrom , which stops the navigation only if the FLEEING entry it removes was keyed to that player: a horse running from two people is still running from the other one and re-picks it on the next beat. flee 's own no-candidate branch stops the navigation on the same condition rather than unconditionally, and the condition is the point. Stopping every beat that finds nothing to run from would cut the legs off whichever goal has the navigation instead — FoodTemptGoal walking a calmed horse back over, most of all, which is the exact behaviour this change exists to allow.
