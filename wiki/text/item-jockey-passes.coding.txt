Jockey passes
(Item / trading)
Lending somebody your horse for an afternoon. A pass is made out to one animal by its owner, handed to whoever is going to ride it, and fed to that horse to buy a day in the saddle — and then it runs out on its own, which is the whole point of it.

Where it lives data/RidingPassAttachment — one map, player UUID to the game time their pass runs out. Registered as horsegenetics:riding_pass , serialised, copyOnDeath , and not synced : the refusal happens on the server, and a client that knew would only be able to predict it wrong. server/JockeyPassHandler — the item's three moments, on PlayerInteractEvent.EntityInteract . server/HorseJockeyCommand — the four command forms. item/JockeyPassItem — the tooltip, which is the only part that has to exist on the client. Two item ids sharing one class, reusing the bound_horse component the stall signs already defined. server/HorseRiding.mayRide — where it is actually read. The pass is asked before the teams, deliberately mayRide asks, in order: the config flag, untamed, the owner, a live pass , then the teams. The pass sits above the teams so that it still works on a server which has set behaviour.riding_allows_teams = false . They are unrelated answers — one is a standing relationship and one is a receipt with a date on it — and one flag silently gating the other would be a trap rather than a setting. A map of deadlines, not a set of names The same call passification 's attachment makes, for the same reason: one map with a time in it cannot disagree with itself, whereas a set of names beside a map of expiries eventually will. Reading it is one comparison. Deadlines are game time , which does not advance while the server is down — so a pass bought for a race is not spent overnight while nobody is playing. grant counts from the existing deadline when one is still running and from now when it is not, which is what stops a second pass being worth less than the first, and every write prunes what has lapsed so a horse does not carry a dead jockey's name in the save for ever. All three of those are invisible from inside the game if they are wrong: a second pass that overwrote the first would look identical on the day it was fed and would quietly have cost somebody a day. So they are the one part of this with a test — jockey_passes_add_up , which was checked against a deliberately broken grant to make sure it bites.
