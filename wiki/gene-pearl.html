Pearl

One copy does nothing. Two copies with no cream give a mild, uniform dilution of both pigments — classic pearl, an apricot body with sepia points. With cream present, cream is the driver and this gene is inert.

Why it is tagged incomplete dominant

Read on its own, prl looks purely recessive — one copy is invisible. But Cr/prl acts as a double cream, so the heterozygote is its own thing once the locus is considered as a whole. That is what the tag records, and it is why the genotype catalogue gives all three pearl pairs their own entry.

It is also the honest signal that the real model is one locus, not two — the MATP merge retires this gene.

Its one job, and the precedence override

Because prl is recessive, the default “first allele in the list is most dominant” ordering would print pairs the wrong way round. Pearl overrides precedence so that N sorts first and a heterozygote canonicalizes as N/prl, keeping the visible allele last:

common/genetics/genes/PearlGene.java
@Override
public int precedence(Allele allele) {
    // prl is recessive; put N "first" so N/prl canonicalizes with the visible allele last
    return allele.equals(N) ? 0 : 1;
}

@Override
public boolean isVisible(AllelePair pair, Genotype genotype) {
    // pearl only "drives" when there's no cream and it's homozygous
    return CreamPearlDilution.creamDose(genotype) == 0
        && CreamPearlDilution.pearlDose(genotype) == 2;
}
A worked example of cross-gene visibility

isVisible gets the whole genotype, not just its own pair — which is how pearl knows to stand down when cream is present, without either gene reaching into the other’s internals. Both genes then call the same resolver, and the resolver decides which mode applies. That is the pattern to copy for any pair of interacting loci.
