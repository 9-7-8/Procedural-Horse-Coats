For modders

Writing a gene

A gene declares its alleles, how they segregate, how dominant the variant is, and one coat function — either a natural pigment restriction or a magical RGB tint, never both. There are two ways to write one: a JSON file, which needs no code at all, or a Java class for anything the format cannot say. This page covers both; Class abstractions is the reference.

Try the file first

Most genes are one shape and one number. Silver dapple is “multiply eumelanin by 0.45 and leave phaeomelanin alone”; a sock is “drive both pigments to zero up the bottom 40% of each leg, jittered”. Neither needs a class. Build it in the gene creator — which previews it on a 3D horse over any base coat — export the JSON, drop it in config/horsegenetics/genes/, restart. The format reference is The gene file format.

Come back here when you need something the format cannot express: reading another gene's dose (cream reads pearl), or rewriting both pigment channels together against a reading of the coat (grey's remap onto the gradient's neutral column). Those are still classes, and always will be — the point of the file path is that you rarely reach for one.

What is and isn't open

Genes is an open registry for data-driven genes: Genes.register(SpecGene) appends after the eighteen built-ins, sorted by declared priority then key, so registration order never decides how a horse looks. A Java gene from another mod still has to be added to this repository — the mod-bus registration hook, the declarative builder and the abstract base classes are designed and on the roadmap. Everything else on this page — the interface, the contract, the pipeline, the determinism rules — is live and applies to both kinds of gene.

What a gene is allowed to do

A gene has four kinds of effect, and may have any combination:

  1. The natural coat — restrict eumelanin / phaeomelanin in phase 1. Reserved for genes that exist in real life.
  2. The artificial coat — add or remove signed R/G/B in phase 3.
  3. Minecraft behaviour — a data-driven gene may carry an effects block: walk on water, resist fire/fall, trail particles, be milked for a fluid. A closed set of five verbs with boolean when conditions — full reference and the "add a new effect" contract in Gene effects. (attribute and mob_effect parse but are not executed yet.)
  4. Status effects — stats, body size, health. Not built yet; sketched in Roadmap §6.
Natural or magical, never both

The two coat effects are mutually exclusive and the choice is declared (Gene.isNatural()), not inferred. A gene that wants both registers as two genes. The separation is a promise to the player that the real-world genetics are real — see Philosophy §6.

Allele rules

Binding on every gene, this mod’s and anyone else’s:

  • Tokens are alphanumeric — a-z, A-Z, 0-9, nothing else. That keeps the code string’s / and - separators unambiguous for free, and it lets real scientific allele names (SW1, W36, D1, TE2) be used verbatim.
  • Length 1 to 128, with strong guidance to keep it to 1–5. Tokens end up on pen signs, in the info panel and in the genotype code; a 40-character token is legal and will look terrible everywhere.
  • Unique within the gene, and the gene key must be namespaced <modid>.<gene>.
  • The wild type is the least magical version, and by convention it is named n. For a real-world gene that is the ordinary allele; for a magical gene it is “this horse does not have the magic”. Naming it consistently matters more than it looks: n is the most-printed token in the mod, and GeneCodeDisplay.shortForm leans on recognising it to keep a genotype readable.
  • An indefinite number of alleles is the design target. Two is the common case, not the assumption — though multi-allele support is not finished (dominance is still declared per gene rather than per pair).
  • Most dominant first in alleles(). That list is what precedence() reads to canonicalize an AllelePair. Override precedence if your ordering needs to differ — pearl does.

The interface

common/genetics/Gene.java — everything you must or may answer
public interface Gene {

    // --- required ---------------------------------------------------------
    String key();                          // "<modauthor>.<gene>"
    List<Allele> alleles();                // most dominant first
    Allele wildType();                     // the "no visible effect" allele
    DominancePattern dominance();          // declared metadata
    int priority();                        // processing order; no default (see below)
    AllelePair randomPair(Rng rng);        // one wild-population draw

    // --- phase declaration ------------------------------------------------
    default boolean isNatural() { return true; }

    // --- exactly one of these ---------------------------------------------
    default PigmentField restrict(AllelePair pair, CoatBuildContext ctx,
                                  PigmentView coat) { return null; }

    default ColorField tint(AllelePair pair, CoatBuildContext ctx,
                            PigmentView coat, ColorView colour) { return null; }

    // --- cache correctness -------------------------------------------------
    default boolean isVisible(AllelePair pair, Genotype genotype) {
        return pair.anyVisible();
    }
    default boolean isDeterministic(AllelePair pair, Genotype genotype) {
        return pair.allDeterministic();
    }

    // --- rarely overridden -------------------------------------------------
    default int precedence(Allele allele) { ... }   // lower = more dominant
    default Allele fromToken(String token) { ... }  // token -> allele
}

Walkthrough 1 — a natural gene

This one has since shipped

Silver dapple landed as a built-in on 2026-09-02 (horsegenetics.silver, common/genetics/genes/SilverGene.java) — so this walkthrough now doubles as a description of a real gene. Your own gene would use a mymod.* key; everything else is unchanged.

The smallest useful shape. Silver dapple dilutes eumelanin only, so a chestnut carrying it looks unchanged — a single restrictAll call is the entire coat effect.

a natural gene, end to end
public final class SilverGene implements Gene {

    public static final String KEY = "mymod.silver";
    public static final int WILD_ODDS = 60;              // 1 in 60 per allele

    /** Eumelanin kept. Phaeomelanin is untouched, so a chestnut is unchanged. */
    private static final float KEEP_BLACK = 0.45f;

    public final Allele Z = new Allele(KEY, "Z", "Silver (Z)", true,  true);
    public final Allele n = new Allele(KEY, "n", "Wild-type (n)", false, true);
    private final List<Allele> alleles = List.of(Z, n);   // most dominant first

    @Override public String key()               { return KEY; }
    @Override public List<Allele> alleles()     { return alleles; }
    @Override public Allele wildType()          { return n; }
    @Override public DominancePattern dominance() { return DominancePattern.DOMINANT; }
    @Override public int priority()             { return 35; }   // natural band; a dilution, so after agouti (20)

    @Override
    public AllelePair randomPair(Rng rng) {
        return new AllelePair(
                rng.nextInt(WILD_ODDS) == 0 ? Z : n,
                rng.nextInt(WILD_ODDS) == 0 ? Z : n);
    }

    @Override
    public boolean isVisible(AllelePair pair, Genotype genotype) {
        // nothing to dilute on a horse that makes no black pigment
        return pair.has(Z) && genotype.hasBlackPigment();
    }

    @Override
    public PigmentField restrict(AllelePair pair, CoatBuildContext ctx, PigmentView coat) {
        if (!pair.has(Z)) {
            return null;                                  // no contribution
        }
        PigmentField f = coat.mutableCopy();               // never write through `coat`
        CoatRegions.restrictAll(ctx.skin(), f,
                (field, px, py, p) -> field.dilute(px, py, 1.0f, KEEP_BLACK, 0.12f));
        return f;
    }
}

Notes on that

  • Allele(geneKey, token, label, visible, deterministic) — the last two are population-level hints. The authoritative per-horse answers come from isVisible / isDeterministic.
  • Returning null is the cheap answer when the pair does not express. Do it; the composer skips the copy entirely.
  • Use dilute, not a bare restrictBlack, whenever the effect is a dilution — the zero-red column is a trap.
  • isVisible sees the whole genotype, which is how a gene declines to run on a base that has nothing for it to do.

Walkthrough 2 — a magical gene

Phase 3 works on a signed, uncapped ColorField. Two shapes matter, and the difference is whether the gene needs to know what it is painting over.

Shape A — a blind, unconditional add

The gene commits hard enough that nothing can pull the horse back. This is order-independent and needs no read access: 

@Override public boolean isNatural() { return false; }

@Override
public ColorField tint(AllelePair pair, CoatBuildContext ctx,
                       PigmentView coat, ColorView colour) {
    if (!pair.has(Blu)) {
        return null;
    }
    ColorField delta = ColorField.deltaLike(colour);
    HorseSkinGeometry.forEachTexel(ctx.skin(), (px, py, part, face, point) -> {
        // A resolved channel tops out at 255, so -510 lands hard on 0 and
        // +510 lands hard on 255, whatever else the horse carries.
        delta.add(px, py, -510, -510, 510);
        delta.addOpacity(px, py, 255);   // so it shows on a dominant-white horse too
    });
    return delta;
}

Shape B — read the accumulator, then walk toward a target

When the gene wants a specific colour and wants to keep the shading underneath, a blind add cannot do it: to reach pink on a black mane a fixed delta has to push so hard that a pale mane saturates to white. Read ColorView.visible first and return the delta that lands where you want:

the pattern PinkHairGene uses
/** The signed step from this texel's accumulated channel to its target one. */
private static int toward(ColorView colour, int px, int py, int channel, int target) {
    int seen   = colour.visible(px, py, channel);       // what a viewer would see
    int wanted = (int) Math.round(seen + (target - seen) * (STRENGTH_PERCENT / 100.0));
    return wanted - switch (channel) {                  // minus what is already there
        case 0 -> colour.red(px, py);
        case 1 -> colour.green(px, py);
        default -> colour.blue(px, py);
    };
}
Reading makes your gene order-dependent

That is a legitimate choice — but it means your position in Genes.magicalOrder() now matters, so pick your priority() deliberately and say so in the gene’s Javadoc. Pink hair (110) runs before magic zebra (120) precisely so that stripes black out pink hair rather than the other way round.

Flat paint (set) is almost never what you want

ColorField.set replaces the accumulator instead of adding to it. It is reserved for a COMPLETE_DOMINANT gene that must read identically on black, chestnut or white — Test is the only one. Using it makes your gene strictly order-dependent and erases every gene before it.

Randomness: the epigenome, and nothing else

A non-deterministic gene takes all its randomness from ctx.epigeneticsFor(key()). That returns a SeededRng on the epigenetic seed of the allele copy that expresses at your gene — the dominant copy on a heterozygote, the higher-priority copy on a homozygote. 

Rng epi = ctx.epigeneticsFor(KEY);

// Document the draw order. It is part of your gene's contract: change it and
// every existing horse carrying this gene changes appearance.
long   seed    = epi.nextLong();                         // a noise field seed
double spacing = 2.2 + epi.nextFloat() * 2.0;            // body units
double reach   = 0.35 + epi.nextFloat() * 0.60;          // fraction of the drop
  • Founders roll a fresh seed; a foal inherits the copy’s seed verbatim, so your pattern runs in families for free.
  • Declare isDeterministic(pair, genotype) false whenever the pair expresses. The usual one-liner is return !isVisibleVariant(pair);.
  • Prefer normalising against bounds(skin, part) / bodyBounds(skin) rather than hard-coded numbers, so the effect works on the foal mesh too.

The contract

A violation shows up as someone else’s horse rendering wrong

Coats are cached per texture key and shared by every horse with that key. A gene that is not a pure function of its inputs does not render wrong — it renders as another horse’s coat.

  1. All randomness through ctx.epigeneticsFor(...). No new Random(), no Math.random(), no RandomSource from the level.
  2. No input the texture key does not capture. Not entity UUID, position, world seed, wall-clock time or tick count.
  3. No mutable static state. Your gene is a singleton shared by every horse on the server; a cached field is a cross-contamination bug.
  4. Return a contribution; never write through your arguments. coat is the previous gene’s output and the next gene’s input.
  5. Declare isDeterministic honestly. Claiming determinism you do not have poisons the cache for every horse sharing your genotype.
  6. Declare the phase honestly. Magical unless the gene exists in real life, and never both.
  7. Do not depend on load order. Every ordering the engine uses is (or will be) computed by sorting.
  8. Only inspect lower-priority genes in a genome-aware spawn chance — the higher ones have not been rolled yet.

Registering it

A data-driven gene registers itself: every .json in config/horsegenetics/genes/ is loaded at startup, in filename order, and placed after the built-ins by its declared priority. Nothing below applies to it. A Java gene is three edits:

common/genetics/Genes.java — three edits, today
public static final SilverGene SILVER = new SilverGene();  // ...among six more added the same day

// 1. the genotype code string's segment order - APPEND, never insert
private static final List<Gene> CODE_ORDER =
        List.of(EXTENSION, AGOUTI, WHITE, TEST, CHAMPAGNE, SPLASH, GREY, CREAM, PEARL,
                MAGIC_ZEBRA, PINK_HAIR, DUN, SILVER, MUSHROOM, ROAN, TOBIANO, FRAME, SABINO);

// 2. phase-1 effect order - position matters, see below
private static final List<Gene> NATURAL_ORDER =
        List.of(EXTENSION, AGOUTI, SILVER, MUSHROOM, DUN, CREAM, PEARL, CHAMPAGNE, GREY, WHITE,
                ROAN, TOBIANO, FRAME, SABINO, SPLASH);

// 3. (magical genes go in MAGICAL_ORDER instead)
Phase-1 order is a dependency order, not a preference

Multiplicative restriction commutes — except where a gene sets pigment absolutely. Bay sets its points with setBlack(1.0) / setRed(0.0), and the whole PigmentField.dilute design exists because the dilutions have to run after that. So: absolute setters early, dilutions later. Silver must sit after agouti or a bay’s mane will not lighten, and nobody will know why.

Every ordering is derived: Genes sorts every registered gene — built-in and data-driven alike — on (priority(), key), and naturalOrder() / magicalOrder() are that list filtered by phase. Natural band 0–99, magical band 100+ (a convention — out of band only warns). Within the natural band, give an absolute pigment-setter a low number and a dilution a higher one — agouti (20) must run before PigmentField.dilute or a bay’s mane will not dilute. The current natural order is extension (10) → agouti (20) → silver (30) → mushroom (32) → dun (34) → cream (40) → pearl (42) → champagne (50) → grey (55) → white (60) → roan (70) → tobiano (72) → frame (74) → sabino (76) → splash (80). Pick a number in a gap; ties break alphabetically by key.

Then

  1. Write the gene up. Add a page under wiki/ modelled on an existing gene page, and add it to the SECTIONS array in wiki/nav.js.
  2. Bake samples: ./gradlew :common:bakeCoatSamples writes build/coat-samples/*.png without launching the game.
  3. Run the tests: ./gradlew :common:test.
  4. Regenerate the golden file if the gene deliberately changes an existing coat: delete common/src/test/resources/coat-golden.txt, run the test, copy common/build/coat-golden.txt back — and say so in the commit message.
  5. Add an entry to To be verified saying what to look at in-game and where.

Testing a gene on its own

Because both hooks are pure, a gene is unit-testable against a synthetic coat with no game and no composer — which is what GeneCoatHookTest does: 

Genotype g   = Genotype.parse("E/E-a/a-w/w-t/t-c/c-spl/spl-g/g-N/N-N/N-n/n-n/n");
Epigenome ep = Epigenome.fromSeed(1234L);
CoatBuildContext ctx = new CoatBuildContext(g, ep, Skin.ADULT, true);

PigmentField before = new PigmentField(HorseSkinGeometry.SHEET_SIZE);
PigmentField after  = new SilverGene().restrict(pair, ctx, before);

// `before` must be untouched, and `after` must be a pure function of the inputs.

Things that will bite you

SymptomCause
Your dilution leaves jet-black pointsYou scaled black without a blackTint. The gradient’s zero-red column reads black down to black ≈ 0.4. Use dilute.
Your effect should read grey and reads tanYou scaled both pigments, walking down the gradient’s diagonal, which runs through the golds. Walk toward the red = 0 column instead.
Your magical gene is invisible on a white horseYou added colour but not opacity. A transparent texel needs addOpacity or set.
Your pattern has a flat band on the chest, rump or leg frontsA pure function of X puts every face perpendicular to X at one phase. Add a slant on |z| — or just use BodyStripes.
Your pattern has a visible seam at the shoulderYou sampled noise in texture space. Sample in body space with BodyNoise.
A marking ends in a perfect ringA hard y <= cutoff cut. Use a smoothstep fade, as BayCoat does.
Two horses with different genotypes share a coatA texture-id collision. KEY_BY_ID should throw — if it did not, your textureKey inputs are wrong.
Your gene works on adults and breaks on foalsThe foal mesh has no MANE or MUZZLE, and its head / neck use rest-pose AABBs. Guard with hasPart.
Near-black texels in a cremelloExpected — that is the white template’s own shading surviving the multiply. Check PigmentField values, not composed pixels.
