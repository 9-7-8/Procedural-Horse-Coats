Dated first, as START HERE says

    ReproRules.NATURAL_CAP was 8, a compile-time constant, and ServerConfig had no fertility
    option but gestation_days — the only "crowding cap" in it was a word in a comment about
    which refusals earn a chat line. Nothing in wiki/verification.html claimed it. Genuinely
    absent, not stale.

Why eight was wrong, and not merely small

    The radius is sixteen blocks, about a chunk, and it counts foals and wild horses and
    reaches straight through walls (only YardPens narrows it, and only inside the yard).
    So eight is not "eight brood mares" — it is a barn, its foals, and whatever is standing
    on the other side of the fence. On the owner's heavily modded server that meant a normal
    stable was over the cap permanently.

    The failure mode is the same one the stallion's day had that morning, one verdict along:
    CROWDED is a refusal the owner does hear about, so instead of silence they got a yellow
    line every five minutes telling them to empty a paddock that was not, by any ordinary
    reading, full. Fifty is roughly "this pen is genuinely packed" rather than "you own more
    than one family".

The shape: the cap travels with the count

    common/ cannot see a config (hard rule 1), and the number is quoted in three places —
    the decision, the owner's chat line, and two log lines. Passing a second bare int beside
    othersNearby would have let any of them drift back to the constant, which is exactly how
    a line that says "the limit is 8" on a server set to 200 gets written.

    So NaturalCover.Crowd is a record of both: how many horses are around her, and how many
    this world allows. It is built in the one place that counts them —
    NaturalBreedingHandler, from ServerConfig.nearbyHorseCap() — and read by
    NaturalCover.decide (crowd.tooMany()) and CoverNotice.line (crowd.cap()) alike. The
    constant survives only as ReproRules.DEFAULT_NATURAL_CAP, the default the option starts
    on, with MAX_NATURAL_CAP bounding it because the same number sits inside a per-scan
    entity search.

    Server-authoritative came free: ServerConfig is the server spec, the count happens on
    the server in an entity tick, and no client is asked. The new option is
    fertility.nearby_horse_cap, 1 to 1,000, default 50.

    cover() gained the crowd as a parameter rather than being handed a 0. Three of the four
    reasons it reports ignore the number, but a call site that passes a made-up one is the
    thing this whole record shape exists to prevent.

What the tests pin

    NaturalCoverTest.aWorldMayRaiseOrLowerTheCap — the same crowd of twelve refuses under a
    cap of eight and covers under a high one. That is the assertion that stops anything
    downstream reading DEFAULT_NATURAL_CAP back. The existing cap test was rewritten against
    the default rather than the constant's old value, and CoverNoticeTest now asserts the
    line quotes the cap it was handed, not a compiled-in one.

Where it lives

    common/repro/ReproRules — DEFAULT_NATURAL_CAP (50) and MAX_NATURAL_CAP replace NATURAL_CAP.
    common/repro/NaturalCover — the Crowd record; decide takes it.
    common/repro/CoverNotice.line — takes a Crowd, quotes its cap.
    neoforge/ServerConfig — NEARBY_HORSE_CAP and nearbyHorseCap().
    neoforge/server/NaturalBreedingHandler — builds the Crowd; both log lines read it.
