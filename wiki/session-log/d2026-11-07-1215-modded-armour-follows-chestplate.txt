- e4f0bc57 (#296, open, waiting on its owed tests). Problem: a modded horse armour gave
  iron's body value for any ingot and diamond's for any gem, because no other item's
  armour can be read at registration (components are not bound; see
  wiki/compatibility.html#components-not-bound). Fix:
  neoforge compat/ModdedArmourValue handles ItemAttributeModifierEvent, which fires
  whenever a stack's modifiers are read, by which point components are bound. For a
  modded armour it replaces the body-slot minecraft:armor.body modifier with the value
  of that mod's own <material>_chestplate (any namespace but ours, first by id). That
  value is the chestplate's chest-slot ADD_VALUE armour, run through common/gear/
  ArmourCurve. Each value is cached per armour and cleared on TagsUpdatedEvent. A read
  that throws is not kept, and no chestplate means the registered guess stays. The
  value is logged as "compat: <id> follows <chestplate> (chest N) - M on a horse".
  ModdedArmour's class note and wiki/compatibility.html (generated-strength,
  components-not-bound, the drift list, gap-282 narrowed to the metalsmith's flat
  trade tier) now say this.
