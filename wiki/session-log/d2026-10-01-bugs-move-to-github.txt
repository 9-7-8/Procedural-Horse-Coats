    No code changed this session. It changed where bugs are recorded, and filed the
    ones that were waiting.

    The rule. The owner asked for a self-piloted "run tests" routine: audit the test
    yard, build and delete pens, launch, read the log, close what passed, fix small
    bugs, and report the large ones for later. Asked where bugs should go, she chose
    GitHub issues for EVERY bug found, including ones fixed in the same run, so the
    fix commit and the yard PASS that proves it close the issue together. CLAUDE.md
    hard rule 9 now carves bugs out of the Verification tabs. Unproven runtime checks,
    design calls, documentation contradictions and compatibility checks stay on the
    tabs as before. Labels: `bug` for every defect; `found-in-yard` for one a yard run
    found; `needs-owner` for one that waits on the owner's decision. A test run
    surveys every open issue, testers' included, except `needs-owner`, and takes the
    ones a pen, a test or a small fix can settle. Removing `needs-owner` after
    answering puts an issue back in the queue.
