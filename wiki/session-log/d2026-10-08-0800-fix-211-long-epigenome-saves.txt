Fix #211, commit e550c9dd. Issue CLOSED.
- What was wrong: NBT writes every string with DataOutput.writeUTF, which stops at 65,535
  bytes. A worst-case epigenome code is 58,726 bytes and grows with every gene that has an
  epigenetic schema. EpigenomeSizeTest asserted only against the 131,072 wire cap, so it
  could not see this limit.
- What going over really does (the issue left it unverified): nothing fails. NbtIo.write
  wraps its output in StringFallbackDataOutput, which catches the UTFDataFormatException,
  logs "Failed to write NBT String" and writes an EMPTY string. A horse over the limit
  would reload with no epigenome.
- The fix: the limit is the JDK's and cannot be raised, so a long code is saved in pieces.
  common/genetics/CodeChunks holds the rule (fitsOneString, split, join). A code that fits
  is written as the bare string it always was; a longer one as a list of 16,384-character
  pieces. GenomeCodeCodecs.STORED_EPIGENOME is the one codec (Codec.either of a string and
  a string list). HorseRecordCodecs, StoredGenome, TransferDeedCodecs and ReproCodecs'
  sample use it. HorseAncestryData, the stasis and afterlife snapshots and the record
  payloads (ByteBufCodecs.fromCodec) go through the horse record's codec, so they are
  covered. Both shapes read: no existing save changes, and no save written today differs.
- Proof:
  - :common:test --tests '*CodeChunksTest' (3 tests). It checks the rule against
    DataOutputStream.writeUTF itself: 65,535 bytes writes, 65,536 throws, three-byte
    characters count as bytes, every piece of a split code writes and joins back whole.
  - New gametest long_epigenome_still_saves in ModGameTests. A 70,000-character code
    goes through the record, seed-jar and transfer-paper codecs to bytes and back, and
    the record across the wire. Run before the codec change: red, "a horse record with a
    70000-char epigenome came back from disk different", with the "Failed to write NBT
    String" ERROR beside it. Run after: "All 56 required tests passed" (55 before this
    test was added).
  - Also green: '*EpigenomeSizeTest', '*CommonPortabilityTest', :neoforge-26.1.2:build,
    check-parity.mjs (7163 checks), check-designer-boots.mjs, check-links.mjs.
- Docs in the same commit: wiki/architecture.html#verified-nbt-string-cap records the
  fix; wiki/api-notes.html#nbt-string-limit records the NbtIo quirk.
- Pictures: no pictures. Nothing about this bug can be seen.
