PROCEDURE  : Audit CLAUDE.md
COMMAND    : /audit-claude-md
SAY        : "audit CLAUDE.md", "audit claude md", "is CLAUDE.md over budget", "clean up
             CLAUDE.md", "trim CLAUDE.md"
RUNS       : either
TAKES      : CLAUDE.md, and a starting point (this session's first commit, or the last
             audit)
LEAVES     : CLAUDE.md at most 300 lines, holding only standing rules and pointers;
             everything else moved to where it belongs
==============================================================================

WHEN TO USE
-----------
Use it:
- at the end of every session (end-session, step 5);
- whenever a session added to CLAUDE.md;
- whenever the owner asks.
CLAUDE.md is loaded into every session, so every line in it costs every task. It was
thousands of lines once, almost all of it material with a wiki page of its own. The cost
was that the rules nobody may break sat buried under session history. "Did I add
anything?" is too easy to answer "no" to without looking, so actually run the checks.

BEFORE YOU START
----------------
Know the session's starting commit. `git log --oneline` and find it. Use HEAD~1 only if
the session made one commit.

STEPS
-----
1. Measure. Run all three:
     wc -l CLAUDE.md                          (must be 300 or fewer)
     git diff <start>..HEAD -- CLAUDE.md      (what did this session add?)
     grep -nE '20[0-9]{2}-[0-9]{2}-[0-9]{2}|[0-9]{3,}' CLAUDE.md
   Count with wc. PowerShell's Measure-Object -Line skips blank lines, and has read 250
   on a 300-line file.

2. Run every ADDED line through the test at the top of CLAUDE.md:
     "Would I need this on EVERY task, before I know what the task is?"
   A line that fails moves out, to where the routing table at the top of CLAUDE.md
   says:
   - a session's work, or anything dated -> wiki/session-log/
   - how a gene, system or class works -> its wiki page
   - a defect -> a GitHub issue
   - a gap, an unchecked assumption, something to look at in game -> that page's
     Verification tab
   - unstarted work -> that page's Roadmap tab
   - a design call -> wiki/decisions.html
   - an API quirk -> wiki/api-notes.html
   - a ROUTINE (steps someone carries out when named) -> a procedure (step 4)
   - a derived number -> the accessor that computes it, named instead of its value
     (Genes.codeOrder().size(), never the count). This is the repeat offender.

3. Check the grep hits from step 1. A date usually means session-log material. A long
   number is usually a derived value that should be an accessor name. The budget
   itself (300) and the test's own example dates are the expected exceptions.

4. Find routines hiding as rules. A paragraph that tells a session what to DO, in order,
   when something happens is a procedure. Move it to procedures/<slug>.txt (FORMAT.txt),
   register it (INDEX.txt, a .claude/skills wrapper, and the keyword memory), and leave
   ONE pointer line in CLAUDE.md. A table that is looked up during a routine belongs
   inside that routine. The regenerate table moved into rebake this way.

5. Find duplication. CLAUDE.md must not copy:
   - a procedure's steps;
   - a wiki page's content;
   - another section of itself.
   Two copies drift, and the stale one gets obeyed. Keep the principle in CLAUDE.md and
   the steps in one place.

6. Check that every pointer still resolves. Every path, page, class, task and procedure
   CLAUDE.md names must exist: grep or ls each one that the session touched or renamed.
   A rule that names a file that is gone is worse than no rule.

7. Over 300 lines means moving a WHOLE section out: to a procedure, or a wiki page, with
   one pointer left. Never trim words to squeeze under the line; 299 lines of history
   has already failed. When you add a line, look for one to delete.

8. Commit CLAUDE.md on its own, or with the docs commit (end-session, step 6). The
   commit message says what moved where.

DONE WHEN
---------
wc -l is 300 or fewer, every line the session added passes the test, no routine or copy
is left in CLAUDE.md, every pointer resolves, and it is pushed.

NEVER
-----
- Never let CLAUDE.md grow past 300 lines "for now".
- Never trim words instead of moving a section.
- Never put a date, a derived number, a session's story or a routine's steps in
  CLAUDE.md.
- Never delete a hard rule to make room. Move the material around it instead, and ask
  the owner before changing a rule's meaning.

SEE ALSO
--------
end-session (step 5); FORMAT.txt (how a moved routine is written); rebake (the
regenerate table, which lives there now); the top section of CLAUDE.md itself.
