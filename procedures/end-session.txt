PROCEDURE  : End a session
COMMAND    : /end-session
SAY        : "end the session", "wrap up", "we're done for today", "end session"
RUNS       : local (it builds); a cloud session skips the build and process steps
TAKES      : a session's worth of work, finished or stopped at a clean point
LEAVES     : code and docs pushed as two commits, docs true, nothing left running
==============================================================================

WHEN TO USE
-----------
At the end of every working session, and as the last part of /process-intake, /fix-bug
and /release. The order is fixed. The docs pass comes AFTER the code is pushed, so it
describes where the session landed rather than narrating a change half-made.

BEFORE YOU START
----------------
Know which files the session touched: `git status --short` and `git diff --stat`.

STEPS
-----
1. Regenerate what the session invalidated, by the rebake procedure. It walks CLAUDE.md's
   "Regenerate what you invalidate" table row by row, against the files that changed. If CustomHorseSpawnScreen or the horse designer changed, fix the
   other one too (hard rule 5).

2. Build green.
   Run `./gradlew :neoforge-26.1.2:build` and `node wiki/gene-creator/tools/check-parity.mjs`.
   If common/ or web/ moved, also run `node wiki/tools/check-designer-boots.mjs`. Do not
   pipe Gradle output to tail: that masks the exit code. Log to a file instead.
   Do not push red. If you truly must, say so in the commit message and file a GitHub
   issue for the failure.

3. Commit and push the code.
   a. Read `git status --short` first. If build or run output shows up, a .gitignore
      pattern is wrong: fix the pattern, never `git add` around it.
   b. Untracked files in intake/ are the owner queuing material. Commit around them.
   c. Work on main; do not branch. Pull first: cloud routines also push to main.
   d. Write one descriptive commit that says what changed and why, not a file list.

4. Update the docs to what is true now, not to "what I changed today".
   Walk CLAUDE.md's page map and honour the source-of-truth rule. At minimum:
   a. a new dated file in wiki/session-log/, plus its entry in wiki/session-log.html;
   b. the Verification tab of each page the session built on: what is newly unplayed,
      and where to look. Delete only what the owner confirmed in game, or what an
      automated PASS answered. Then run bake-verification-index.mjs;
   c. any bug discovered goes in a GitHub issue (see report-bug), never on a page;
   d. any gene or system page the session moved;
   e. wiki/pages.js, if a page was added (hard rule 7);
   f. build-search-index.mjs, check-links.mjs and bake-agent-text.mjs, for any prose.

5. Audit CLAUDE.md and put it back under budget. Actually run all three:
       wc -l CLAUDE.md                     (must be at most 300 - wc, not Measure-Object)
       git diff <session start>..HEAD -- CLAUDE.md
       grep -nE '20[0-9]{2}-[0-9]{2}-[0-9]{2}|[0-9]{3,}' CLAUDE.md
   Run every line the session added there through the test at the top of CLAUDE.md:
   would every task need it, before the task is known? A line that fails moves out. A
   date means session-log material. A long number is a derived value, which should be
   named by its accessor instead. Over 300 lines means moving a whole section out,
   not trimming words to squeeze under.

6. Commit and push the docs as their own commit. Step 4 always leaves the tree dirty.

7. Verify clean: `git status --short` empty, and `git log origin/main..HEAD` empty.

8. Kill every process this session started.
   This covers Gradle daemons and workers, any runClient or runServer, and every
   background shell. Kill the game and server processes first, then
   `./gradlew --stop`: a daemon still running a build ignores the stop.
   Leave the owner's own terminals alone. If a client is up that you did not launch,
   ask before closing it (see launch-game).

9. Stop, with a short summary. Say what shipped, what is newly waiting in
   wiki/verification.html, and the one thing the next session should pick up first.
   Say too whether a release looks due, by release step 1. If one does, offer it; never
   cut it unasked.
   Then stop: no new work, no "while I'm here" refactors.

DONE WHEN
---------
- Both commits are on origin/main and the tree is clean.
- CLAUDE.md is 300 lines or fewer.
- No process this session started is still alive.
- The summary is given.

NEVER
-----
- Never run the full :common:test suite as part of this. It takes ten minutes or more,
  and the owner will not wait. Name in the summary what a full run would still check.
- Never commit a post-bake `git status` that only changed timestamps. `git diff` is
  the authority.
- Never leave doc changes unpushed. The owner reads the live wiki.
- Never close a Minecraft client the owner is playing in.
